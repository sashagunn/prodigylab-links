# IndexNow — prodigylab.studio

IndexNow — протокол мгновенного уведомления поисковиков об изменениях. Один POST-запрос уходит сразу в **Bing, Yandex, Seznam, Naver** (они делят один эндпоинт). Google протокол не поддерживает.

Смысл: не ждать, пока краулер сам зайдёт через неделю, а сказать «эта страница изменилась» в момент деплоя.

---

## Что уже сделано

| Что | Где |
|---|---|
| Ключ | `36a8f3d2d56a946777c590357b4fbf40` |
| Файл ключа | `/36a8f3d2d56a946777c590357b4fbf40.txt` в корне репозитория, содержит ровно ключ и ничего больше |
| Публичный адрес ключа | `https://prodigylab.studio/36a8f3d2d56a946777c590357b4fbf40.txt` |
| Скрипт | `scripts/indexnow-submit.js` |
| Состояние | `.indexnow-state.json` (в `.gitignore`) |
| Логи | `logs/indexnow/YYYY-MM-DD.jsonl` (в `.gitignore`) |

Файл ключа **обязан быть доступен по HTTP** — поисковик скачивает его, чтобы убедиться, что заявку подал владелец домена. Если файл пропадёт, все заявки начнут отклоняться с 403.

## Команды

```bash
npm run indexnow
```
Отправляет **только изменившиеся** страницы. Скрипт считает sha1 каждого локального файла и сравнивает с `.indexnow-state.json`. Если ничего не поменялось — не отправляет ничего и пишет об этом в лог. Это защита от спама: IndexNow не любит, когда один и тот же URL шлют каждый день без причины.

```bash
npm run indexnow:dry
```
Показать, что бы ушло, ничего не отправляя. Используй перед первым запуском и после крупных правок.

```bash
npm run indexnow:all
```
Отправить все URL из sitemap принудительно. Нужен ровно два раза: при первом запуске и после массовой правки шаблона. Не гонять регулярно.

```bash
node scripts/indexnow-submit.js https://prodigylab.studio/ai-automation/
```
Отправить конкретные URL руками.

```bash
npm run seo
```
Полный цикл: пересборка CSS → пересборка sitemap → отправка изменённых URL в IndexNow.

## Порядок при обычном деплое

```bash
npm run css        # если трогал Tailwind-классы
npm run sitemap    # если добавлял или удалял страницы
git add -A && git commit -m "..." && git push origin main
# подождать ~40 секунд, пока Vercel раскатает
npm run indexnow
```

**Важно:** `npm run indexnow` запускать **после** пуша, а не до. Поисковик пойдёт по URL проверять содержимое; если новая страница ещё не раскатана, он увидит 404 и заявка сгорит впустую.

## Как читать логи

`logs/indexnow/2026-09-03.jsonl`, по строке на событие:

```json
{"ts":"2026-09-03T...","event":"submit-ok","status":200,"count":11,"urls":[...]}
{"ts":"2026-09-03T...","event":"skip","reason":"no-changes","candidates":32}
```

Коды ответа:

| Код | Значение | Что делать |
|---|---|---|
| 200 / 202 | принято | ничего |
| 400 | кривой формат запроса | смотреть тело ответа в логе |
| 403 | ключ не найден или не совпадает | проверить, что `https://prodigylab.studio/36a8f3d2d56a946777c590357b4fbf40.txt` открывается и внутри ровно ключ |
| 422 | URL не с этого домена, или ключ не тот | сверить `host` и `keyLocation` в скрипте |
| 429 | слишком часто | притормозить, не запускать чаще раза в день |

При любой ошибке скрипт **не обновляет** `.indexnow-state.json` — следующий запуск повторит отправку. Так изменение не потеряется.

---

## Ограничения, которые надо помнить

- IndexNow — это **уведомление, а не гарантия индексации**. Поисковик придёт быстрее, но решает сам, брать страницу в индекс или нет.
- За раз протокол принимает до 10 000 URL, скрипт шлёт пачками по 500.
- Никаких данных о позициях и трафике IndexNow не отдаёт — только «принял / не принял». Аналитика живёт в Bing Webmaster Tools.

## Если ключ придётся сменить

1. Сгенерировать новый: `openssl rand -hex 16`
2. Создать в корне `<новый-ключ>.txt` с этим ключом внутри.
3. Удалить старый `.txt`.
4. Удалить `.indexnow-state.json` — иначе скрипт решит, что ничего не изменилось.
5. Задеплоить, дождаться раскатки, запустить `npm run indexnow:all`.

Скрипт находит ключ сам — он ищет в корне файл вида `[a-f0-9]{8,128}.txt` и проверяет, что содержимое совпадает с именем. Править код при смене ключа не нужно.
